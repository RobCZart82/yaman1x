# H8 SCI internal cycle clock

Implementation: [PR #28](https://github.com/RobCZart82/yaman1x/pull/28).
Date: 2026-10-27. Local native tests and scheduling differential PASS.
Serial byte state machine, CPU scheduler and firmware integration: NOT RUN.

`H8SciCycleClock` adapts only the integer-cycle internal-clock scheduling in
the pinned MAME `h8_sci.cpp`. Source hashes/authorship are recorded in
`research/h8-sci-clock-provenance.json`; BSD-3-Clause terms remain in
`licenses/MAME-BSD-3-Clause.txt`. This is not a complete SCI device.

## Exact boundary

Supported modes are internal async, internal async with clock output, and
internal sync with clock output. Configurations selecting an external clock
are rejected before changing state; neither external pin clocks nor the
upstream floating-point external-rate approximation are implemented.

The divider is `2 << (2 * CKS)`, multiplied by `BRR + 1`. It is a cycle tick
divider, not a baud rate: the async serial state machine still needs its
16-phase TX/RX counters. The adapter assumes no AN1x CPU or DSP frequency.

The first side to start aligns the event to the next strict divider boundary.
TX uses the owner's `total_cycles`; RX uses its distinct `now_as_cycles` view.
Starting the other side shares the running event/step. Starting an already
active side is a no-op. A newly started side returns true so the future serial
owner can set its phase counter to 15, as upstream `clock_start` does.

`configure()` changes the divider/mode, while an already active internal clock
keeps its existing step and event until restart. `stop()` removes that side;
the last stop clears the event/step. Standby exit offsets a pending event by
`total_cycles - standby_time` using caller-supplied cycle values.

## Scheduling and callback contract

`service_one(horizon, tx, rx, idle_clock)` processes **one** due edge even when
the horizon is far beyond the event. This preserves the upstream
`internal_update()` granularity. An owning scheduler must repeatedly service
overdue events with an explicit work budget; this class is not that scheduler.
Advancing a large block once is therefore insufficient.

At an edge, TX precedes RX. Callback dispatch mode is selected at entry;
RX's active flag is checked after TX, so a TX callback can stop RX before it
ticks. When all sides stop at an edge in an output-clock mode, `idle_clock()`
signals the upstream release-high operation. Ordinary stop is not itself a
manufactured edge. The adapter performs no bit output or receive sampling.

No callbacks fire before an event is due. Register/MMIO access order, IRQ
delivery, system-wide sync scheduling and external line changes belong to
the future machine owner. The upstream `sync_tick` timer only forces a
system-wide sync; it is not an extra serial tick source.

Startup and standby arithmetic reject overflow/invalid order before state
mutation. If a callback throws or arithmetic fails after a callback has ticked,
the owner must discard its partially advanced machine; callback effects cannot
be rolled back. No real-time deadline guarantee is claimed.

## Validation and reproducible evidence

Local Windows MSVC Release native test PASS:

- All 1024 CKS/BRR combinations and distinct TX/RX start-time views.
- Shared phase, duplicate-start suppression, restart and active reconfiguration.
- Identical event sequence under different owner block partitions, with a
  bounded test scheduler and TX-before-RX ordering.
- No early callback, one-event late service, callback-driven stopping and
  latched dispatch mode, standby adjustment and two-instance independence.
- Unsupported external mode, invalid standby order and startup overflow.

An isolated reference fixture used the verbatim pinned upstream scheduling
method bodies, omitting the logging-only block and supplying stub sync/CPU
services and tick counters. Xorshift32 seed `0x3a17b` drove 200000 mixed
configure/start/stop/update/standby operations at bounded cycle values.
Event, step, divider, mode, active sides and TX/RX tick counts matched after
every operation: **zero mismatches**, MSVC Release. The temporary fixture stays
outside Git. This is not a byte-state-machine or full MAME differential.

The standard CTest suite covers the adapted component on the next PR's
platform builds. Final tested revision/CI links are recorded in that PR.
The separately built research MAME executable still uses its original SCI.
